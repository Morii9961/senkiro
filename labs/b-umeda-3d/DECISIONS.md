# 建模与工程决定

| 决定 | 考虑过的备选 | 理由 |
|---|---|---|
| 从本地 main 创建指定分支的独立工作树 | 在仓库根检出目录修改 | 开工时根目录在另一个实验分支，目标本地分支尚不存在。工作树放在仓库既有的忽略目录中。 |
| 在本地 .local 加载 transit-station-3d 工作流和参考材料 | 将技能包随开源仓库发布 | 用户提供的技能只用于开发。共享契约优先，按其一次性交付与本地提交要求执行。 |
| 选择 Osaka Metro 梅田 | 阪急大阪梅田 | 2026 年 6 月大阪市换乘图 B 段给出两家改札间的连续路径，Metro 设施页可继续追到 1 号站台。 |
| 分开 JR 大阪、Metro 梅田；本实验的 complex 只登记这两个可步行换乘的站点 | 按「梅田」文字合并附近车站 | 相同地名无法证明同一运营方、闸内互通或全日开放。周边其他站点只作带提示的独立体块。 |
| 每家站点拥有独立 Level，跨街区段另设 Level；按 ordinal 做同层展示 | 对齐不同图纸的海拔、方位与尺寸 | 运营商资料可以核对层序与停靠，无法标定公共测量坐标。3D 间距、轨枕、踏步、扶手、闸机数量和门宽均为绘图约定。 |
| 聚合 Metro 坡道及其局部中间平台，保留独立坡道段 | 给短高差自设楼层名称 | 运营商标明坡道及ホーム～中階电梯，大阪市表按 B1F 改札至 B2F 站台描述。坡度和中间平台标高未知。 |
| 保留 JR 西口至うめきた的绕行层序 | 从 B2F 连络通道直接走到同层站台 | 两端图的 AB、AC、AD／AE 电梯对应关系显示要先上 B1F，再下到站台。 |
| 以 Gate 边精确定义进出闸，以停靠点之间的设施边定义换层 | 用两个场景体块相接的距离生成路线 | 画面接近不构成可通行证据。路径成本按闸数、换层、段数作字典序比较。 |
| 确认无台阶模式只使用 stepFree=true 的段，方向未知的扶梯不可寻路 | 把资料空白当成无障碍或默认扶梯双向 | 资料确认、临时维护、尺寸适配是不同问题。示例不会承诺设备此刻可用。 |
| 自绘几何、按需 WebGL 绘制和独立 SVG 分图 | 使用运营商图片或以 3D 截图作为平面图 | 可离线构建、按层阅读、对照稳定 ID，WebGL 初始化失败时仍能打开 2D。 |
| 手工核对事实与运行示例分开 | 把抓取时刻或许可不明的运行数据放入构建 | 当前无已授权的实时输入。示例固定为 2000 年，让日期、来源及模式始终可辨认。 |
