# UX_SPEC · 产品与交互规范

> 先读 `CURRENT_STATE.md`。本文回答"做成什么样、为什么"；组件细节见 `UI_COMPONENTS.md`，数据形状见 `DATA_CONTRACTS.md`，顺序见 `IMPLEMENTATION_PLAN.md`，验收见 `ACCEPTANCE_TESTS.md`。
> 标记：【沿用】= 用现有代码；【重构】= 局部重写；【新增】= 目前不存在。

## 1. 产品原则

1. **默认界面属于普通乘客。** 打开后第一件事是"我要去哪"，不是"这是什么建筑"。不需要理解模型就能找到站台、检票口、出口。
2. **三维是空间的解释者，不是装饰。** 3D 与信息面板共享同一个选择；点击任何东西，场景必须有可见反应。
3. **诚实优先于完整。** 没有数据的字段显示「未確認」（不隐藏，也不填充）；合成/模拟数据始终带醒目标识；不做假实时；不出现来源不明的距离、时间、无障碍、线路色。
4. **信息密度高、层次清楚、克制。** 参照成熟的日本铁路导航产品：少装饰、强层级、稳定的位置与形状。禁止用"全部放大字号"解决标签问题。
5. **Astra 的建筑不动。** 不重建车站模型；3D 不退化成 2D 图层；2D 是并列的第二视图。

## 2. 三类使用者与信息架构

三类人共用一个界面，靠**"表示の深さ"**而不是登录身份区分，默认最浅：

| 层（`detail` 取值） | 面向 | 显示内容 | 默认 |
|---|---|---|---|
| **案内** `guide` | 普通乘客 | 车站名、线路徽章、站台号、主要检票口/出口、路线；详情卡只放"去哪、怎么去" | ✅ 默认 |
| **設備** `facility` | 铁路爱好者 | + 楼梯/扶梯/电梯/厕所等设施图标、方向（目的地）、车型/列车（有数据时） | |
| **構造** `structure` | 城市/交通空间研究者 | + 建筑构件与辅助通道名称、层号/ID/来源编号、几何置信度、数据性质（derived / manual-verified / synthetic） | |

- 切换位置：画布右下角分段控件「案内 / 設備 / 構造」。它是标签级别的**上限**：`labelTierShown = min(zoomTier, detailCap)`（guide=2、facility=3、structure=4），不是另一套界面。【新增】
- 信息架构（右侧面板 4 个页签，移动端为底部页签）：

| 页签 | 内容 | 来源 |
|---|---|---|
| **探す** Search | 搜索框、分组结果、最近查看、常用路线预设 | 【新增】 |
| **経路** Route | 起终点、无台阶开关、摘要、分楼层步骤列表、逐段导览 | 【重构】自 `main.tsx` |
| **列車** Trains | 运行模式、时钟、列车列表/卡片；无数据时给出清晰的"未提供"说明 | 【新增】（阶段 4 后才出现） |
| **情報** Info | 模型范围、资料来源、数据性质图例、已知限制（原 `Guide.tsx`） | 【重构】 |

- 详情卡不是页签：它是选中对象时在面板顶部展开的"对象页"（见 §6），可关闭，关闭后回到当前页签。

## 3. 版面

- **桌面（≥ 900 px）**：左 3D/2D 画布，右侧 360 px 固定侧栏（面板 + 对象页）。**对象详情不再浮在画布左上角**（现状遮挡站名牌）。画布内只留：视图切换 3D/2D、车站选择器、缩放/复位、楼层控制、"案内/設備/構造"。
- **窄屏（< 900 px）**：画布全宽；面板为底部抽屉，三段高度（收起 72 px / 半屏 / 近全屏），选中对象时自动升到半屏，再次点画布空白处收回。
- 标签布局要把面板与控件占用的矩形作为**禁区**（safe insets）传入布局引擎，标签不得被控件盖住。

## 4. 对象类型与状态

### 4.1 可选对象（`SelectionTarget.kind`）

`station`（Station / context 站点）· `platform` · `gate`（Link.kind='Gate'）· `entrance`（Place.kind='Entrance'）· `passage`（Link.kind='Passage'，含换乘通道）· `vertical`（Stairs / Escalator / Elevator）· `concourse`（Place.kind='Concourse'）· `line`（RailLine）· `train`（阶段 4 后）。`Landing` 不可选（内部节点）。

### 4.2 视觉状态（所有对象共用同一套）

| 状态 | 触发 | 3D 表现 | 标签表现 |
|---|---|---|---|
| `default` | — | 材质原色 | 按分级显示 |
| `hover` | 指针悬停（桌面） | 描边/提亮一档，`cursor:pointer` | 标签提亮并强制显示 |
| `selected` | 点击/搜索/列表 | 实例色换为强调色 + 外轮廓，镜头聚焦 | 标签加粗放大一档，必显 |
| `related` | 与选中对象有业务关系（同线路站台、选中检票口两侧设施…） | 轻度强调（线路色细边 / 次级强调色） | 必显，次级样式 |
| `dimmed` | 选中后其余对象 | 实例色向背景色混合 ≈ 55%；**仍可点击**（点中即切换选择） | 降级一档、半透明 |
| `onRoute` | 属于当前路线 | 路线橙（沿用 Astra 的 `routeColor`），当前步更深色 | 路线标签必显 |
| `unavailable` | 数据缺失 | 不改变 3D；详情字段显示「未確認」灰字 | — |

实现要求见 §7；高亮通过**修改实例颜色**完成，不得触发场景重建。

## 5. 标签系统（行为规范；视觉见 UI_COMPONENTS §1）

### 5.1 分级

| 级别 | 内容 | 现有来源 → 新来源 | 出现区间 |
|---|---|---|---|
| **L1** | 车站名、大型换乘枢纽（梅田地区各站、Whity、JR 大阪/うめきた） | `Scene.tsx` 站名牌 → 由 `Station`/`context` 生成 | 远景～中景；近景退场（`maxBand=mid`） |
| **L2** | 线路徽章、站台号（带线路色）、主要检票口、出入口/出口（名称以「口」结尾或有编号）、楼层角标 | 站台 `pin`、Gate `pin`、`floor-pin` | 中景起；远景只显示"每站的线路徽章簇" |
| **L3** | 楼梯、扶梯、电梯、厕所等设施（图标优先，文字悬停/近景） | 路线步骤标签 | 近景，或选中/路线上 |
| **L4** | 建筑构件、辅助通道、Concourse 名、Landing、ID/技术信息 | Concourse `pin` | 仅 `structure` 层且近景 |
| **L0（常驻）** | 选中对象、路线起终点与当前步、悬停对象、楼层角标 | — | 永远显示，不受缩放/避让淘汰 |

### 5.2 缩放带（`zoomBand`）

- 度量：`pxPerUnit = 画布高度(px) / (camera.top − camera.bottom) × camera.zoom`（正交相机）。
- 三个带：`far < Z1 ≤ mid < Z2 ≤ near`。**Z1、Z2 由 Sol 在固定机位截图上标定**，写进 `src/scene/labels/config.ts`，不得散落魔数。
- **回差**：升带要越过阈值 +12%，降带要低于阈值 −12%，避免缩放停在阈值附近时闪烁（新宿 `labels.ts` 同法）。
- 单层视图（`floor !== null`）和有路线时，每级标签提前一带出现（同新宿）。
- 总览（全層）远景只显示 L1 + 每站线路徽章簇；**绝不**所有级别同时出现。

### 5.3 布局（纯函数，可单测）

输入：候选标签（锚点屏幕坐标/深度、尺寸、级别、优先级、是否上一帧可见、是否被遮挡）、视口、禁区。输出：每个标签的最终位置 / 是否显示 / 是否画引导线 / 是否折叠为簇。

1. **按带过滤**（含回差）；L0 无条件保留。
2. **遮挡剔除**：用代理包围盒（每个 Place 的楼板 AABB + Osaka 外壳屋顶）从相机向锚点做射线，被其他楼层/外壳挡住的标签直接剔除（L0 除外，L0 改为淡化并加"隐藏"提示）。不要对 97k 三角面逐标签射线。
3. **优先级排序**：`priority = 基础(级别) + 选中/路线加成 + 上一帧可见加成(小于级别间隙，防闪烁)`。
4. **候选位置**：锚点上方 → 右 → 左 → 下 → 四角；位移不超过 `MAX_LEADER = 48 px`；位移 > 12 px 画细引导线；仍冲突则：L0 强制保留并略偏，其余按优先级淘汰。
5. **越界钳制**：标签中心钳制进"视口 − 禁区 − 8 px 边距"，最多位移 24 px；超过则隐藏（L0 贴边并显示指向箭头）。
6. **簇与同义折叠**：同类 ≥4 个互相重叠（如阪急 9 条站台）折叠成范围芯片「1–9」（新宿 `trackRange`）；同文字、同类型的标签在 `SAME_MEANING_PX` 内只显示一个（路线上的不折叠）。
7. **预算**：每 10 000 px² 画布最多 1 个非 L0 标签，总数不超过 40。
8. **稳定性**：位置变化做 120 ms 过渡；显隐做 120 ms 淡入淡出；相机拖动中可降频到每 2 帧布局一次，静止后做一次完整布局。
9. **距离约束**：标签与目标的屏幕距离始终 ≤ `MAX_LEADER`，否则隐藏而不是漂远。

### 5.4 标签内容规则

- 站台标签 = 线路徽章 + 站台号（「3·4」）；站名不重复写在每个站台标签里。
- 线路徽章颜色只能来自 `LineStyle.color`（有来源）；`null` 时用中性灰徽章 + 线名文字，**不得用硬编码色冒充**（现状 `Scene.tsx:521–528` 的三色硬编码要移除）。
- 站名牌点击 = 选中**车站**（`kind:'station'`），不再落到 `jr-11` 站台（现状缺陷）。

## 6. 点击与详情对象页

### 6.1 通用层次（所有类型一致）

1. **标题与身份**：类型图标 + 主名（ja/en 随界面语言）+ 副名 + 身份芯片（LineBadge、楼层、闸内/闸外、运营商）。
2. **关键交通信息**：这个对象对旅客最重要的 3–5 行（见各类型）。
3. **地理/空间关系**：邻接对象的**可点击列表**（点击即切换选择）。
4. **可执行操作**：主按钮「ここから」「ここへ」「経路」，次按钮「この階だけ表示」「乗客目線」。
5. **补充与来源**：数据性质芯片、几何置信度、来源列表（标题/日期/链接）、「未確認の項目」清单。

字段缺失一律渲染为：`项目名  未確認`（灰字，`title` 说明缺什么资料）。禁止隐藏字段行，也禁止用推测值填充。

### 6.2 各类型内容

**站台 platform**
- 关键：运营公司、线路（徽章）、のりば番号、楼层、闸内；**方向/主要目的地**（`Platform.directions`，null → 「方面：未確認」）；**列车信息区**（见 §9，随模式而变，默认「リアルタイム配信なし」）。
- 关系：同站相邻站台；**换乘线路**（经寻路图派生：到其他线路站台的 `改札数 / 階層移動`，标注"派生・示意"）；最近的检票口、竖向设施（图邻居，点击可选）；相邻站（`Station.neighbors`，数据缺失→未確認）。
- 操作：ここから／ここへ／この階だけ表示／乗客目線。

**检票口 gate**
- 关键：名称、所在楼层、**两侧区域**（闸内→闸外，及两侧所属车站/运营商）、关联线路与站台（派生：从闸内侧经无其他改札的路径可达的站台）、**无障碍**（来自 `stepFree`，null → 未確認；"幅広改札/车椅子通行"无数据则不写）。
- 关系：通往的主要设施与出口（闸外侧 2 跳内的 Entrance/Concourse/竖向设施）；**换乘方向**（跨运营商 Gate 写"JR ⇄ 御堂筋線"）。
- 操作：ここから／ここへ／「この改札を通る経路」。

**换乘通道 passage**
- 关键：连接的两个空间（名称+楼层+闸内外）、楼层变化（无 / A→B）、涉及线路（两端车站线路并集）、管理者（`Place.manager`）、通行时段「未確認」。
- 关系：沿线设施；3D 中以路线样式显示这条通道的方向箭头；**距离/时间：「未測定」**（不得估算）。
- 操作：この通路を含む経路／ここから／ここへ。

**出入口 entrance**
- 关键：出口编号/名称（`Entrance.exitLabel`，null → 未確認）、地面对应位置（`surfaceNote`，来源缺 → 未確認）、最近的车站区域（图最近的 Concourse/Gate）、**可达线路**（从该口出发经最少改札可达的线路，派生）。
- 操作：**ここへ**（主按钮，"从当前选中位置到该出口的路线"= 把出口设为终点；起点为当前选中的站台/检票口，无则提示"出発地を選択"）。

**竖向设施 vertical**
- 关键：类型图标、A 层 → B 层、**是否无台阶**（Elevator=是；Stairs=否；Escalator=否；以 `stepFree` 为准）、运转方向（扶梯 unknown → 「方向未確認・経路には使いません」）、服务站台（派生）、稼働状況「未確認（配信なし）」。

**车站 station / 线路 line**
- station：运营商、线路徽章簇、楼层列表、站台数、与其他站的步行连接（经图）；操作「この駅だけ表示」「この駅の見どころ(乗客目線)」。
- line：徽章、运营商、本区域内的站台列表（点击切换选择）；选中后 3D 中该线路站台 `related`、其余淡化。

### 6.3 与选择状态联动（硬性契约）

- **唯一真相**：`selection = { kind, id } | null`。点击 3D、点标签、点搜索结果、点面板里的关系列表、点 2D 平面、点路线步骤，**全部通过同一个 `select()`**。面板标题、3D 高亮、标签加粗、2D 高亮、地址栏 `?sel=` 永远一致。
- 违反即缺陷：面板显示 A，3D 突出 B（验收 AT-SEL-04）。
- 选中时：① 对应对象高亮；② 其余 `dimmed`；③ 镜头 600 ms 缓动聚焦（`easeInOut`，保持正交轴测方向，调整 target 与 zoom；楼层不匹配时先切楼层）；④ 面板展示对象页；⑤ 相关线路站台 `related`；⑥ 可直接启动路径规划。
- 取消选择：点画布空白 / `Esc` / 对象页关闭按钮 → 淡化解除，镜头**不回退**（避免眩晕），除非用户按「⟲」。
- 楼层控制：选中对象在被隔离楼层之外时，自动切到该对象所在展示层（并提示）；用户手动切楼层不清除选中，但若对象不在新楼层，对象页保留、3D 显示"该対象は別の階にあります → 移動"。

## 7. 3D 联动的实现约束（给架构定方向）

- 保持 Astra 的单个 `InstancedMesh`。`owners[i]` 已是实例→对象 ID 的映射：高亮 = 遍历 `owners`，对命中实例改 `instanceColor`（选中色/原色/向背景混合色），`instanceColor.needsUpdate = true`，**无需重建几何**。需要保存原色数组 `baseColors`。
- 一个对象常对应多个 owner（如站台有 `sk:platform:x`；检票口是 Link id；楼梯整段 id）。定义 `ownersOf(target): Set<string>`：站台 → 自身；车站 → 该站所有 Place + 其 Link；线路 → 该线 `serviceLineIds` 命中的站台。放在 `src/domain/index.ts`，可单测。
- 外轮廓：用同一 owner 的实例再画一遍略放大的反面材质（`BackSide`），或后处理描边；**选其一并记入 DECISIONS**。不做逐帧全屏后处理（软件渲染下会卡死）。
- 重建 key：只有 `siteId / floor / spread / shell / eye / 路线步 / lang(标签文字)` 变化才重建几何或标签；`selection / hover / 主题 / 模式` 变化只改外观。
- 相机缓动：`controls.target` 与 `camera.zoom` 在 600 ms 内插值；动画期间每帧 `draw()`，结束即停（保持按需渲染）。

## 8. 搜索【新增】

- 入口：右侧面板「探す」页顶部输入框（`/` 键聚焦）。
- 索引对象：车站、站台（含"3・4"番号与线名）、线路、检票口、出入口/出口、竖向设施、Whity 区段；字段：`names.ja / names.en / ja_kana(若有) / 站台号 / 线路名 / 车站名`。规范化 NFKC、全半角、`・`/`·`/空格互通、大小写不敏感。
- 排序：完全匹配 > 前缀 > 包含；同分时 站 > 站台 > 线 > 检票口/出口 > 设施；当前楼层/当前站的结果加权。
- 结果行（统一样式，见 UI_COMPONENTS §3）：左图标/线路徽章，主名，副行「车站 · 楼层 · 闸内外」，右侧 `↳` 操作（设为起点/终点）。
- 点击结果 = `select()`（同 §6.3，镜头聚焦 + 打开对象页）；键盘 ↑↓ Enter。
- 空状态：最近查看 5 项 + 「よく使う経路」（现有 6 条 `tours`，标注"编辑部预设"，点击=设起终点并规划）。
- 无结果：显示"该名称未收录"，不自动联想成别的站。

## 9. 列车与运行信息（UX）

### 9.1 四个概念，界面上永远分开

| 概念 | 含义 | 来源 | 界面标识 |
|---|---|---|---|
| **官方时刻表** | 运营商/开放数据发布的原始时刻 | 带 SourceRecord、许可、日期 | 列表里的「予定 hh:mm」，标明来源与版本日期 |
| **时刻表模拟** | 用官方时刻表按规则推算的示意位置 | 上一行 + 显示常量 | 蓝色横幅「時刻表に基づく模擬位置です。実際の列車位置ではありません」 |
| **演示虚拟时刻** | 项目自造的夹具 | `synthetic`，来源以 `demo:` 开头 | 橙色横幅「DEMO · 架空のダイヤ」，列车卡带「架空」，**不得**出现在默认视图 |
| **实时列车数据** | 授权实时源 | 目前不存在 | 无源时界面写「リアルタイム配信なし」，不出任何动的"当前列车" |

- 默认关闭（`mode='off'`）。用户在「列車」页显式选择：`時刻表シミュレーション`（仅当该区域有真实时刻数据）/ `デモ`。数据不足的站台**不上轨、不画车**（"不知道番线就不上轨，不猜"）。
- **缺少数据时，虚拟列车绝不能被显示为真实正在运行的列车**：同一画面不允许 demo 与 timetable 混用（新宿 `validateDataset` 已有此规则，沿用）。

### 9.2 列车体验

- 沿正确轨道行进：进站减速→停车（门开闭）→出站加速（参数是显示常量，写在 `trains/constants.ts` 并注明"非运营数据"）。
- 选中列车 = `select({kind:'train'})`：卡片显示 列车种别/行先（来自时刻记录原文）、线路徽章、停靠站台、予定到着/出发、车型（`verified / representative / unknown` 徽章；unknown 画中性泛用车体并写"車種未確認"）、编组长度（未知→「編成未確認」，不假定 10 节）、阶段（接近/停车/出发）。
- 「追従」按钮：镜头跟随；用户拖动即取消。
- 车型外观不得"所有线路同一种泛用列车"：按线路/种别区分车体比例、编组、涂装（程序化即可，数据驱动，见 DATA_CONTRACTS §7）。

## 10. 导航体验

### 10.1 状态机

`idle` →（选起点）→ `fromSet` →（选终点）→ `planned` →（开始）→ `stepping` →（到终点）→ `arrived`；任一状态可「クリア」。

### 10.2 起终点

- 来源：对象页的「ここから/ここへ」；搜索结果右侧 `↳`；面板里两个"槽位"（可点击聚焦、可搜索替换）。
- 选定后槽位显示 LineBadge + 名称 + 楼层；一键「⇅ 入れ替え」。
- 现有 `<select>` 长列表 **移除**（保留为无障碍后备：键盘用户用搜索框即可）。预设 `tours` 移到「探す」空状态。

### 10.3 路线呈现

- **面板**：摘要「N 区間 · 階層移動 N 回 · 改札 N 回」；明确写「距離・所要時間：未測定」（灰字，一行）。步骤按**楼层分组**，每组头显示 `1F → B1F` 楼层变化条；步骤行 = 图标（改札/階段/エスカレーター/EV/通路）+ 动作 + 去向 + 无障碍小标（`stepFree` true/false/null）。
- **3D**：全層视图下画一条**贯穿所有楼层的连续路线折线**（沿真实边的端点，竖向设施处画垂直"升降段"），其余楼层/对象淡化；当前步加粗并带前进箭头；逐段导览沿用 Astra 的取景逻辑并加缓动。【重构】`Scene.tsx` 路线部分。
- **楼层变化提示**：每个竖向段两端各有一个楼层徽章（「▼ B1F」/「▲ 1F」），当前步是换层时画面中央出现 2 秒的提示条。
- **沿途强调**：楼梯、扶梯、电梯、改札用各自图标的 L3 标签（路线上的强制显示，L0）。
- **转弯节点**：折线顶点处画小圆点；**不输出"向左/向右转"指令**——坐标是示意的，转向在现实中可能不同（决定 D-07）。指令只写设施名与去向。
- **无台阶模式**：开关旁一行说明「確認済みの段差なし区間のみ使用。資料の空白は『通行可』とは扱いません」；无路线时列出**阻断原因**（首个无法通过的边：未确认 / 楼梯 / 方向未知扶梯），而不是一句"未確認"。
- **禁止直线**：任何两点之间的路线只能由 `route()` 的 Link 序列生成；没有图连通就不画（现状已如此，**保持并加测试**）。

## 12. 设计决策记录

| ID | 决定 | 备选 | 理由 |
|---|---|---|---|
| D-01 | 三类使用者用"表示の深さ"三档，而非角色切换 | 登录/角色选择；三套界面 | 不增加使用门槛；同一对象在三档下一致，只差信息量 |
| D-02 | 单一 `selection` 为唯一选择状态 | 保留 `picked/placeId/trip` 并同步 | 现状五套状态已导致"模型信息里选的设施 3D 里看不到" |
| D-03 | 保留 DOM 标签，布局引擎抽成纯函数 | 改 Canvas/Sprite 标签；`CSS2DRenderer` | DOM 文字清晰、可访问、已有；难点是布局而非渲染方式，纯函数可单测 |
| D-04 | 高亮用修改实例色，不重建 | 每次选择重建；后处理描边 | 重建太重（见 CURRENT_STATE §3.1）；软件渲染下后处理不可接受 |
| D-05 | 不输出距离/时间 | 按示意坐标估算 | 坐标是"示意单位"，估算等于编造 |
| D-06 | 线路色必须有来源，否则中性徽章 | 凭记忆填色 | 契约：不编造；项目约定不复制运营商符号图标，用"色条 + 线名文字"的自有徽章 |
| D-07 | 不输出左转/右转指令 | 由示意坐标推算转向 | 布局是示意的，转向可能与现实相反 |
| D-08 | 详情放右侧栏/底部抽屉，不浮在画布上 | 保持左上角浮卡 | 现状遮挡站名牌与站台 |
| D-09 | 站名标签选中"车站"，不是某个站台 | 沿用 owner=jr-11 | 站名≠站台 |
| D-10 | 列车默认关闭，必须显式开启，且四类数据分开呈现 | 默认开演示 | 契约 §1.5/1.6：不假实时 |
| D-11 | 状态进 URL（`?sel=&from=&to=&floor=&site=&detail=&lang=`） | 仅内存 | 可分享、可复现 bug、可做深链测试 |
| D-12 | 场景重建受 `geometryKey` 控制 | 保持"每次渲染重建" | 列车动画与高亮的前提 |
