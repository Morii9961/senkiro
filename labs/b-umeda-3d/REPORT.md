# SENKIRO Lab · Umeda Station 3D 验收报告

## 1. 一句话结果

大阪・梅田七座独立车站与 Whity 地下街可分层查看、按站点聚焦及跨站寻路，站台与商业通道支持乘客高度视角。

## 2. 运行环境

2026-11-22 在 Windows x64（10.0.26200）、Node.js 24.15.0、npm 11.12.1 上验收。浏览器为本机 Chromium 158.0.8127.36，无头运行，WebGL 使用 ANGLE SwiftShader。移动端验证使用 390 × 844 CSS 像素的浏览器视口。未测试实体手机和硬件显卡。

## 4. 真实运行记录

- 从本地功能提交 `af3031c` 用 `git archive` 导出原型到新的空目录。执行 `npm install && npm run build && npm test`，退出码 0。安装 63 个包，npm 当次审计报告 0 项。
- 构建校验 171 个节点和 194 条边，完成 TypeScript strict 检查与 Vite 生产打包。主脚本 831.98 kB，gzip 232.49 kB。独立橱窗纹理为 628.94 kB。Vite 提示主脚本超过 500 kB 的默认阈值。
- Vitest 14/14 通过，Playwright 4/4 通过，浏览器用时 26.5 秒。桌面实测涵盖带改札与电梯的逐段导航、点击站台、自选端点、六个新增场景与两种乘客视角。窄屏实测涵盖 2D 分层、来源、运行示例及主题切换。监测控制台和页面异常的用例均通过。
- 开发中一次 Playwright 启动失败，本机 Windows 拒绝监听原默认端口 5193（EACCES）。将默认端口改为经实测可用的 27193，仍可用 SENKIRO_E2E_PORT 覆盖。最终干净目录运行采用新默认端口。
- 在同一干净构建运行 `node scripts/measure.mjs`。1440 × 900 视口、DPR 1、1440 × 734 画布、全区全层总览、建筑剖面开启、抽屉关闭。软件 WebGL 的最终颜色绘制为 3 个 draw call、97,270 个三角面，阴影贴图在几何改变时更新。持续交替平移 3.068 秒，记录 10 次操作、10 次绘制，约 **3.3 帧／秒**。纯软件总览交互较慢；实体 GPU 和手机帧率尚未实测。静止时按需绘制。

## 7. 已知缺陷与风险

六个展示层采用示意间距。同名楼层没有共用海拔承诺。图上长度、方位、设施间隔、外壳、扶手、闸机和轨枕不能用于定位、测量或判断实际通行宽度。站台柱、座椅、栏杆和门机都是自绘图例，位置、数量与现场外观均为示意。闸机数量、升降方向、运营时段及施工期规则未穷举。已知扶梯若方向未知只显示设施，不用于计算路径。

资料可能随施工、改札调整和电梯检修而过期。改札外不等于公共道路或全天通行；街侧横道及地下步行段的具体管理主体和时段未确认。实地复核、当前电梯可用性、自然人无障碍验收、GPU 设备帧率均未验证。3D 总览会遮挡部分路径，单层与 2D 可逐段检查。当前计算仅比较已录入的路径。阪急九股道的乘车／下车专用面尚未逐面细分。Whity 店铺为匿名建筑表现，模型没有真实租户或营业状态。乘客相机固定在选定位置，拖动环顾。

演示列车仅使用阪急既有示意轨道。进出站速度、门动画、无到达时刻时的显示停站都采用原型常量。当前可模拟的列车限于 3D 轴测视图。无已知进站端或仅有聚合站台且无法确定轨道侧的记录不会生成车体。

## 8. 对 SENKIRO 的可复用资产

车站页可从选中的 Station ID 取该实体的 RailLine、Level 与 Place 集合，按 StationComplex 的成员及带来源的 Link 加载跨站部分。Interchange 记录首条 JR→御堂筋线示例，其他可达关系从连接图取得；Whity 是独立的商业区域。用 `data/processed/station.json` 作为版本化静态资源，先用同版本的 `data/sources.json` 校验，再将 `route(model, fromId, toId, liftsOnly)` 输出的 Link 序列交给 3D、楼层图、行程文字与移动端。详情抽屉按 provenance.sourceIds 关联资料、日期与管理方；主站只需携带 station、platform、level 和所选步骤的稳定 ID。

可直接复用 `src/domain/types.ts`、`graph.ts`、纯数据导出、反例测试，以及按 lineId 和 platformId 关联的 PlatformUpdate 协议。车站页需要适配自己的数据加载、语言、主题、相机与深链。生产运行源另接带授权的 provider，处理数据过期、暂停、错误与撤销；示例模式独立开启。现有步行图不参与轨道拓扑、车次运营或计费计算。

扩展京都或其他关西枢纽，需要先按运营商厘清同名 Station、可步行换乘的 complex、站台与服务线路，并记录施工版本。分别核对原图印刷楼层、每个电梯的停靠与方向、出入闸关系；跨公司段要有逐段的官方或市政依据。登记管理者、许可、时效与关闭状态，缺证处保持断开。新增站点数据包后复用端点、跨层、闸内外、连络改札与预期路线的测试。若遇到真正的连络改札，要扩展 Gate 的精确授权站对与来源校验；当前模型一律拒绝跨运营商 paid→paid 边。
