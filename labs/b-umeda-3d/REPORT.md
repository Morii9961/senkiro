# SENKIRO Lab · Umeda Station 3D 验收报告

## 1. 一句话结果

原型可逐层旋转查看 JR 大阪站和 Osaka Metro 梅田站，并演示一条有官方连续依据的跨运营商路线。干净目录通过生产构建、12 项领域测试和 3 项浏览器测试。

## 2. 运行环境

2026-11-21 在 Windows x64（10.0.26200）、Node.js 24.15.0、npm 11.12.1 上验收。浏览器为本机 Chromium 159.0.8154.6，无头运行，WebGL 使用 ANGLE SwiftShader。移动端验证使用 390 × 844 CSS 像素的浏览器视口。未测试实体手机和硬件显卡。

## 4. 真实运行记录

- 从功能提交 `e7309ab` 用 `git archive` 导出原型目录到系统临时目录，确认存在 package.json，初始无 node_modules、dist、本地技能或原图。执行 `npm install && npm run build && npm test` 成功。安装 63 包；此次 npm audit 报告 0 项。
- `npm run build` 完成数据一致性检查、strict TypeScript 和 Vite 生产打包。Vite 报告主 JS 792.51 kB，gzip 218.19 kB，并提示超过 500 kB 的默认 chunk 阈值。
- `npm test` 完成 11/12 项领域测试、2/3 项 Playwright。桌面测试检查非空 WebGL 绘制、跨站八段导航的镜头落点、地图点选、自定义起终点和交换方向、平面图与复位，捕获的浏览器控制台错误及未捕获异常为零。窄屏测试涵盖示例开关、来源、深色、键盘关闭对话框、路线选择和 2D。
- `node scripts/measure.mjs` 在 1440 × 900、DPR 1、1440 × 734 的 canvas 上实测。初始全层总览、紧凑层距、路线抽屉折叠，1 draw call，30,948 triangles。持续约 3.002 秒，每次 requestAnimationFrame 交替键盘平移，35 次操作、35 次绘制，约 **11.7 帧／秒**。此数包含 DOM 标签与软件渲染成本。静止时按需渲染。
- 开发中两次 strict 编译失败，分别为 JSON 坐标推断成可变长度数组，以及示例 feed 联合类型未收窄。修正后通过。首轮受限沙箱浏览器运行未完成，残留本任务预览曾造成 5193 端口冲突，定位并结束对应进程后默认端口通过。首次临时导出未包含 package.json，修正归档起点后按上述命令重新验收。本轮点选站台后的自选路线测试曾因终点选择器的无障碍名称不准确而失败。修正控件标签，并把楼梯场景的测试起点设在中央口闸内，最终全部通过。

## 5. 数据覆盖与许可

JR 与 Metro 本体均为 AI 对照官方资料的 manual-verified 录入。模型保存大阪环状线、JR 神户线、JR 京都线、大阪东线与御堂筋线的代表性关联。站台块可以代表两个番线，录入的线路不穷举所有停靠业务。11 番未指定常态线路。阪急、阪神、東梅田、西梅田、北新地和 Whity 只登记名称依据与未核实范围。

共登记 32 条 SourceRecord，包括图版、网页、网站条款、目录检索与自制示例。JR 构内图日期为 2026-01-14，大阪市换乘图及 Metro 周边分层表为 2026-06。Metro 站页未标可靠资料日期，阪急、阪神的历史图版未用于寻路。读取日另存为 2026-11-21。日期不确定的字段保持 null。

运营商原件保留权利，市政府图件亦未取得本项目的原件再分发许可。本仓库只含用自有表达记录的事实、原创示意坐标与代码；不提供原图、描摹图、网页快照、底图或字体。逐份许可状态见 [SOURCES.md](SOURCES.md)。

ODPT 的公开 CKAN API 对「大阪メトロ」「梅田」「駅施設情報」「阪急電鉄」「JR西日本」五个查询分别返回 0 个匹配；只能说明这些查询未找到可用数据。挑战赛目录列出的东京部分车站步行网络受限定许可。e-Gov 有新大阪地区步行网络的地图条目，索引标示政府标准利用规约第 2.0 版，范围与本任务不同。两者均未用于构建。运行示例为 synthetic，开发者适配器独立于车站数据。

## 6. 与任务书的事实出入

- 开工时仓库根实际处于另一个实验分支。指定的本地分支不存在，已从本地 main 创建独立工作树。
- 大阪站既有区和うめきた属同一 JR 大阪站。西口及うめきた地下口之间有**改札内**连络通道；图上给出的特定通行说明有适用边界。没有扩写成所有乘客都能免费穿站的规则，也没有把通道误接到同层地下站台。
- JR 御堂筋口、御堂筋南口、Metro 中北東改札是三个不同地点。默认演示使用市图 B 的地面横道；御堂筋南口另列为分支。城市图的⑥和 JR 图的电梯字母仅为图内索引。
- 任务书把相邻运营商列为候选。JR 至 Metro 的连续线路有资料支持。其余同名／近名站仍各自独立，没有添加未经验证的改札内跨站关系。
- JR 既有区还有中 2F。1・2 番从御堂筋侧乘电梯需经过图中的中间通路，并在 O、P 两部电梯间换乘。该中间通路有独立楼层、停靠节点和两段电梯，自动化测试从御堂筋口闸内追到大阪环状线 1・2 番站台。中央口、桜橋口的中 2 阶楼梯通路独立建模。

## 7. 已知缺陷与风险

六个展示层采用示意间距。同名楼层没有共用海拔承诺。图上长度、方位、设施间隔、外壳、扶手、闸机和轨枕不能用于定位、测量或判断实际通行宽度。站台柱、座椅、栏杆和门机都是自绘图例，位置、数量与现场外观均为示意。闸机数量、升降方向、运营时段及施工期规则未穷举。已知扶梯若方向未知只显示设施，不用于计算路径。

资料可能随施工、改札调整和电梯检修而过期。改札外不等于公共道路或全天通行；街侧横道及地下步行段的具体管理主体和时段未确认。实地复核、当前电梯可用性、自然人无障碍验收、GPU 设备帧率均未验证。3D 总览会遮挡部分路径，单层与 2D 可逐段检查。当前计算仅比较已录入的路径。

## 8. 对 SENKIRO 的可复用资产

车站页可从选中的 Station ID 取该实体的 RailLine、Level 与 Place 集合，以 StationComplex 的成员及 Interchange 加载跨站部分。用 `data/processed/station.json` 作为版本化静态资源，先用同版本的 `data/sources.json` 校验，再将 `route(model, fromId, toId, liftsOnly)` 输出的 Link 序列交给 3D、楼层图、行程文字与移动端。详情抽屉按 provenance.sourceIds 关联资料、日期与管理方；主站只需携带 station、platform、level 和所选步骤的稳定 ID。

可直接复用 `src/domain/types.ts`、`graph.ts`、纯数据导出、反例测试，以及按 lineId 和 platformId 关联的 PlatformUpdate 协议。车站页需要适配自己的数据加载、语言、主题、相机与深链。生产运行源另接带授权的 provider，处理数据过期、暂停、错误与撤销；示例模式独立开启。现有步行图不参与轨道拓扑、车次运营或计费计算。

扩展京都或其他关西枢纽，需要先按运营商厘清同名 Station、可步行换乘的 complex、站台与服务线路，并记录施工版本。分别核对原图印刷楼层、每个电梯的停靠与方向、出入闸关系；跨公司段要有逐段的官方或市政依据。登记管理者、许可、时效与关闭状态，缺证处保持断开。新增站点数据包后复用端点、跨层、闸内外、连络改札与预期路线的测试。若遇到真正的连络改札，要扩展 Gate 的精确授权站对与来源校验；当前模型一律拒绝跨运营商 paid→paid 边。
