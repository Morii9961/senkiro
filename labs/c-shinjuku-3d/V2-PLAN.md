### 技术债

1. **3D 只是线框和薄板。** 所有东西都是同一种 Lambert 材质的方盒，没有墙、柱、台阶、轨道，没有阴影，看不出体积。
2. **楼层是按运营商分的实体**，界面上因此出现「B1F（京王）」这种标识。数据层这样建是对的（各家自己编号），但不该原样暴露给乘客。
3. **站台只有番线号**，选起终点时看不出是哪条线。
4. **元素详情把内部字段原样列出**（ID、来源 ID、dataNature）。
5. **相机没有步骤聚焦**；中键是缩放而不是平移。
6. **2D 的全部楼层视图**里，滚轮既是页面滚动又是图的缩放，互相冲突。
7. **六个站区只有占位体块**，不是完整的新宿站。

### 数据真实性说明

V1 的数据是 AI 读官方图录入的，没有人复核；几何全部是示意。V2 不改变这一点，新增的站区同样如此。V2 新增的墙、柱、台阶、闸机、轨道等建筑构件，是**根据已有的区域轮廓和连接关系按规则生成的画法**，不是新的车站事实：墙沿区域边界画，在相邻区域的连通处和检票口处留开口；柱只画在站台上，位置是装饰性的。这些会在界面和文档里写明。

## 2. 用户反馈的处理

| 反馈 | 处理 |
| --- | --- |
| 中键应能拖动整个模型 | 中键、右键、Shift+左键都平移；平移范围限制在模型附近 |
| 选站台时要有线路名 | 起终点列表、站台标签、详情里都显示线路名和线路标识 |
| 不要到处强调「京王」 | 界面按楼层（B2F、B1F、1F…）分组，不再按运营商分；数据层保留各家各自的 Level |
| 模型里要有线路标识 | 站台边缘按线路着色，站台标签带线路标识 |
| 详情页面向用户重新设计，去掉调试数据 | 重做。只有站台、检票口、出入口、电梯等设施有详情；站厅和通道没有 |
| 线路图标 | 自行设计的色块标识（线路色 + 线路代号）。契约禁止复制运营商的线路符号，所以不照搬官方图形；代号只在核实后才显示 |
| ODPT 为什么不可用 | 用户决定可用于本地测试。实现开发服务器代理，密钥从仓库根目录 `.env.local` 读取，不进浏览器包，数据不落盘、不进仓库 |
| 2D 全部楼层与滚轮冲突 | 2D 只显示单层 |
| 2D 太草率 | 重画 |
| 未核实的内容要补全 | 逐个读官方构内图：小田急、东京地铁丸之内线、京王新线・都营新宿线、都营大江户线、バスタ新宿。读不到或读不准的仍然如实标注 |
| 不做移动端 | 去掉移动端布局和触屏说明 |

与共享契约冲突、由用户明确决定覆盖的三处：推送到 GitHub（§8）、放弃移动端（§6）、ODPT 用于本地测试（§1.8 的待决事项）。都记入 DECISIONS。

## 3. V2 的目标架构

```
data/manual/                各站区的手工数据，每个运营商一个文件
src/domain/                 不变的领域层 + floors.ts（楼层的显示分组）
src/providers/              车站数据、示例叠加层、ODPT（经开发代理）
src/ui/scene/
  arch/                     建筑生成器：楼板、墙、站台与轨道、楼梯、扶梯、电梯、闸机、柱
  build.ts                  汇总成图元；路线、标签、取景框
  geometry.ts               按材质合并几何体、拾取
  materials.ts              材质与光照参数
  camera.ts                 受限轨道相机、聚焦动画
src/ui/Scene3D.tsx          只做组装
src/ui/Plan2D.tsx           单层平面图
src/ui/panels/              路线、楼层、运行、来源、详情，各一个文件
```

数据层不依赖任何视图；2D、3D、寻路仍然读同一份模型。

## 4. 视觉与交互方案

- **风格**：半写实的建筑剖切模型。屋顶和上层墙体切掉，墙只画到齐腰高，保证路线不被挡住。
- **构件**：有厚度的楼板；沿区域边界的矮墙，连通处留门洞；站台有边缘警示带和按线路着色的边条，旁边是道床和钢轨；楼梯是一级一级的台阶；扶梯是带扶手带的斜梯；电梯是玻璃井道加轿厢；检票口是一排闸机；楼梯和电梯穿过楼板的地方开洞。
- **材质**：少数几种 PBR 材质（地面、墙、混凝土、金属、玻璃、橡胶），用顶点色区分语义，不用贴图文件。环境反射用程序生成的环境，不引入 HDR 图片。
- **阴影**：不用实时阴影贴图（上层楼板会把下层整个罩黑）。用烘焙的办法：墙和构件底部压暗，地面上沿墙根画渐变的接触阴影。
- **相机**：固定倾角的轴测式默认视角；俯仰角、距离、目标点都有上下限；点路线步骤时平滑聚焦到那一段，动画可被任何操作打断，可在设置里关掉。
- **楼层**：全部楼层 / 单层 / 只看路线经过的楼层。
- **路线**：当前步骤高亮，其余路段变淡；带方向箭头。
- **性能**：按需渲染；几何体按材质合并；目标是 1920×1080 和 1366×768 下常规操作 60 FPS，实测后写进 REPORT。

## 5. 实施顺序

1. 交互反馈里能快速修的（中键平移、线路名、楼层分组、去掉移动端）。
2. 3D 建筑实体化，先以 JR 13・14 番线站台到中央通路这一段为样板调好材质和比例，再让生成规则作用于全站。
3. 相机约束、步骤聚焦、路线相关楼层。
4. 2D 重画、详情与运行面板重做。
5. 其他运营商站区的资料核对与录入。
6. ODPT 本地测试接入。
7. 回归测试、性能测量、文档。

每一步结束时构建和测试都要是绿的，并提交一次。

## 6. 不做的事

第一人称漫游、动态人流、列车动画、商铺、照片级贴图、移动端。没有资料依据的通道、楼梯和出口不画。没有实测数据就不输出距离和时间。
