## 已完成

### 1. 深色模式：独立的三维场景主题（需求 B）

- `src/ui/sceneTheme.ts`：模型的材质色板、环境光 / 主光 / 补光、tone mapping、曝光单独成一份配置；
  界面主题（CSS 变量）只决定选哪一份，不再直接压暗建筑材质。
- 深色场景：背景改为石墨色 `#262b33`（原来接近纯黑 `#14181e`）；材质保持各自色相，只略降明度；
  主光加强并略偏暖、补光偏冷，Khronos Neutral tone mapping，曝光 1.06；路线、贴花、描边不参与
  tone mapping。没有任何全局乘色、黑色遮罩或整体降亮度。
- 描边改为向阴影色加深（不是亮线），墙脚与柱脚的接触阴影在深色下加强；深色下浮动标签改成低对比
  的深色小签，线路识别色保留。
- 浅色模式的灯光数值未变；截图核对无退化。
- 同机位对照：全景、B1F 单层、带路线的全景、大江户线站台近景（含列车）四组，浅色与深色逐一目视核对 ——
  深色下模型的材质与浅色一致，变化的只有背景、灯光与标签。**未完成**：对照图是本机临时截图
  （`test-results/shots/`，不入库），没有整理成并排对照文件；“多层剖切”机位没有单独拍。

### 2. 共享时刻表接口（§7、§8）

`src/timetable/`，纯 TypeScript，不依赖 React / three.js：

| 文件 | 内容 |
| --- | --- |
| `types.ts` | `TimetableRecord`：19 个字段与任务书一致（snake_case 原样）；`vehicle_assignment_status` = `verified` / `representative` / `unknown`；预留 `TrainLiveState`（目前只产生 `scheduled`） |
| `registry.ts` | 12 个规范车站 ID（任务书 §8 的写法）↔ 模型内 `sk:station:*` 的稳定映射，`station_complex_id` 分组；16 条规范线路 ID 及 `odpt.Railway:*` 别名；`platform_id` = `<station_id>:<番线>` 的解析 |
| `time.ts` | JST 运营日时间，支持 `24:35`、`25:10`；03:00 前算前一运营日；日别匹配（平日 / 土曜 / 休日 / 土休日等写法）。**不识别日本法定节假日**（没有假日表），界面提供日别选择 |
| `validate.ts` | 只报告、不修补：缺字段、未知车站、公司与车站不符、时间格式、发车早于到站、编组非整数、车型状态与车型不一致、内部 `trip_id` 冒充车次、重复车次、未知来源、同一番线同时两列车、Demo 与正式数据混用 |
| `adapter.ts` | CSV（带引号 / 换行 / BOM）与 JSON 读入；只做拼写归一（空值、`null`、`不明` → null），不补任何值 |
| `demoFixture.ts` | **Demo Fixture**：固定间隔的虚构时刻，所有 ID 以 `demo:` 开头，不带车次、去向、车型、编组 |

交接方式：把 `.csv` / `.json` 放进 `data/timetable/`（说明见该目录 `README.md`），构建时读入；
目录里没有可用记录时整体使用 Demo Fixture，**两者不会混用**（有测试）。格式示例：
`data/timetable-example/demo-fixture.sample.csv`。

**与另一方时刻表的衔接风险**：对方的实际文件还没见到。字段名按任务书逐字实现；`station_id`、
`line_id`、`platform_id` 的具体写法是本原型按 §8 推定的，若对方写法不同，需要在 `registry.ts`
加别名（线路已有别名机制，车站与番线目前只接受表中写法和 `…:<番线>` 结尾）。

### 3. 车辆库与匹配规则（§6）

`src/trains/vehicles.ts`。车型从不按线路颜色推断，依次取自：

1. 记录自带的 `vehicle_series`（状态用记录给的）；
2. 有来源的线路规则；
3. 否则通用占位列车，标 `unknown`。

| 线路 | 车型 | 状态 | 依据 |
| --- | --- | --- | --- |
| 山手線 | E235系 | `verified` | JR 东日本「JR東日本の列車たち：E235系」運行区間列有山手線；读过的 E231、E233 页面没有列山手線 |
| 中央線快速 | E233系 | `representative` | 同站 E233系 页面列有中央線快速；未核对是否每一班 |
| 埼京線 | E233系 | `representative` | 同上；该线有他社直通车 |
| 中央・総武線各駅停車 | E231系 | `representative` | E231系 页面；该线另有其他车型 |
| 其余所有线路 | 通用占位 | `unknown` | 尚未逐一查证（小田急、京王、都营、东京地铁、西武、各特急） |

编组节数只来自记录的 `formation_length` 或有来源的线路事实，**不默认 10 节**。目前唯一的线路事实：
都营大江户线新宿（E27）8 节（都营立体图下方的のりかえ・出口案内表按 1–8 号车编号）。
节数未知时列车画成不分节的整体、不画车门，信息卡写“未知（长度为示意）”。

**缺口**：山手線 E235 的 11 节编组没能取得来源 —— JR 东日本的新闻稿 PDF 拒绝自动访问（403），
之后再用浏览器打开被权限策略拦下，没有绕过。因此 Demo 中的山手线列车目前没有节数。时刻表数据若
带 `formation_length` 会直接生效。

三维模型是本原型自制的简化形体（车体、车顶与空调、转向架、窗带、月台侧可开闭的车门、两端司机室
与头尾灯）。比例、车门数、识别色位置都是示意，颜色是近似值，不是运营公司的色值；没有复制任何照片
或模型。

### 4. 时刻表驱动的列车模拟（§7）

- `src/trains/simulate.ts`（纯函数）：记录 + 时钟 → 列车状态。进站（匀减速）→ 停靠 → 开门 → 关门
  → 发车（匀加速）；通过式番线从一端进、另一端出，尽头式番线原路退出；无计划列车时不显示。
  没有随机数，没有信号模拟。
- `src/trains/trackRuns.ts`：模型内全部 37 条番线的运行方向与通过 / 尽头属性，逐条写明依据
  （运营方印的方面文字 + 模型朝向）。JR 5・6 番线（特急，双向都有）方向未定 → 只显示停靠，不做进出站。
- 小田急同一股道两侧各有一个站台编号：按“物理股道”去重，同一股道同一时刻只有一列车（有测试）。
- 时刻表没有到站时刻时，按 30 秒停站示意，信息卡标“假定”；终到列车（无发车时刻）停 60 秒后撤下，
  不编造回送。
- 渲染（`src/ui/trains/TrainLayer.tsx`）：所有列车共用 **一个** instanced mesh（+1 次 draw call）；
  超出所画轨道端头的部分被裁掉（等于从隧道口进出）。场景仍是按需渲染，只有列车在动或开关门时才连续出帧。
- 界面：舞台左下的时间条始终显示「时刻表模拟 · 非实时列车位置」；使用 Demo Fixture 时另有
  「Demo Fixture（虚构时刻）」标记。当前日本时间模式 / 演示模式（暂停、×1 ×10 ×60、拖动时间、日别）。
  “运行”页有数据说明、按线路 / 站台 / 车型可信度筛选、当前显示的列车列表。
- 列车信息卡：运营公司、线路、种别、终点、计划到站 / 发车、站台、车型与状态、编组、车次（有来源才显示）、
  状态（时刻表模拟 + 当前阶段）、来源与更新时间；可聚焦、隐藏、暂停，不影响路线导航。
- URL 参数：`trains=off`、`simtime=HH:MM[:SS]`、`simplay=1`、`simrate=<n>`。
- 实时状态 `live_adjusted` / `live_position` / `stale` / `cancelled` / `suspended` 只在类型里预留，
  没有任何界面会显示“实时位置”。

## 与任务书、仓库约束的出入

- 任务书要求查证小田急、京王、都营、东京地铁、西武及各特急的车型；本轮只查了 JR 东日本三个车型页面，
  其余线路一律 `unknown`，没有按线路色猜车型。
- 2D 平面图不显示列车（任务书只要求 2D 路线导航保持可用，已有 e2e 覆盖）。
- 列车比例受示意轨道宽度限制：模型里一股道只有 0.62 个示意单位宽，列车因此比站台显得细；
  长度按站台示意长度适配，不代表真实车长。

## 风险

1. **时刻表格式未对接**：见上文“衔接风险”。对方文件到位后需要实际跑一遍校验。
2. **车型事实的来源面窄**：`verified` 只有山手線一条，且依据是车型页的“運行区間”，不是逐班次确认。
3. **JR 东日本站点拒绝自动访问**：新闻稿类 PDF 取不到，编组等事实需要别的官方来源或人工提供。
4. **节假日**：日别不自动识别法定假日。
5. **性能目标未在显卡上验证**；列车很多时每帧要写全部实例矩阵（目前上限 20,000 个盒子）。
6. **西口施工**：新站接入时必须以最新官方资料为准，本轮未涉及。
